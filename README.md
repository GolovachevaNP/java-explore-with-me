## Структура базы данных

Проект состоит из основного сервиса и сервиса статистики.  
Основной сервис использует базу данных `ewm`, а сервис статистики - базу `stats`.

### Основные сущности основного сервиса

- `users` - пользователи
- `categories` - категории событий
- `events` - события
- `participation_requests` - заявки пользователей на участие в событиях
- `compilations` - подборки событий
- `comments` - комментарии пользователей к событиям

### Связующие таблицы

- `compilation_events` - связь подборок и событий

### Сущности сервиса статистики

- `endpoint_hits` - информация об обращениях к endpoint'ам основного сервиса

## Связи между таблицами

- `events.category_id` - категория события, связь с таблицей `categories`
- `events.initiator_id` - пользователь, создавший событие, связь с таблицей `users`
- `participation_requests.event_id` - событие, на участие в котором подана заявка, связь с таблицей `events`
- `participation_requests.requester_id` - пользователь, подавший заявку, связь с таблицей `users`
- `comments.event_id` - событие, к которому оставлен комментарий, связь с таблицей `events`
- `comments.author_id` - автор комментария, связь с таблицей `users`
- `compilation_events.compilation_id` - подборка событий, связь с таблицей `compilations`
- `compilation_events.event_id` - событие в подборке, связь с таблицей `events`

## Дополнительная функциональность: «Комментарии»

Реализована возможность оставлять комментарии к событиям с предварительной модерацией администратора.

### Модель данных

| Поле | Тип / ограничение | Описание |
|---|---|---|
| `id` | `Long` | Идентификатор комментария |
| `text` | `String`| Текст комментария после применения `trim()` |
| `createdOn` | `LocalDateTime` | Дата и время создания. При редактировании не изменяется |
| `status` | `CommentStatus` | Текущий статус: `PENDING`, `PUBLISHED` или `REJECTED` |
| `eventId` | `Long` | Идентификатор события, к которому относится комментарий |
| `authorId` | `Long` | Идентификатор автора комментария |
| `edited` | `boolean` | `true`, если автор редактировал комментарий, который ранее был опубликован |

### Бизнес-правила

- Комментарий можно создать только для существующего события со статусом `PUBLISHED`.
- Пользователь может комментировать собственное событие и создавать несколько комментариев к одному событию.
- Пользователь может изменить или удалить только комментарий, у которого `authorId` совпадает с `userId` из запроса.
- Удаление физическое: комментарий удаляется из базы данных и исчезает из всех списков.
- Администратор может менять статус только у комментария в статусе `PENDING`. Допустимые целевые статусы: `PUBLISHED` и `REJECTED`.
- При редактировании текст заменяется новым валидным текстом, статус меняется на `PENDING`, а `createdOn` остаётся исходной датой создания.
- После редактирования ранее опубликованный комментарий исчезает из публичного списка до повторного одобрения.
- Публичный список содержит только комментарии со статусом `PUBLISHED`.
- Список комментариев автора содержит комментарии со статусами `PENDING`, `PUBLISHED` и `REJECTED`.
- Комментарии к событию со статусом `CANCELED` недоступны через публичный API: запрос возвращает `404 Not Found`.
- Если `commentId` существует, но не относится к `eventId` в пользовательских запросах `PATCH` или `DELETE`, возвращается `404 Not Found`.

### Модерация и статусы

Статусы комментариев:

- `PENDING` - комментарий ожидает проверки администратора; не виден в публичном списке, но доступен автору и администратору
- `PUBLISHED` - комментарий одобрен и доступен в публичном списке
- `REJECTED` - комментарий отклонён; не доступен публично, но доступен автору и администратору

#### Изменение статуса и признака `edited`

- Новый комментарий создаётся со значениями `status = PENDING` и `edited = false`.
- Администратор может изменить статус комментария с `PENDING` на `PUBLISHED` или `REJECTED`.
- Автор может редактировать свой комментарий с любым статусом. После редактирования комментарий снова отправляется на модерацию: его статус становится `PENDING`.
- Поле `edited` становится `true` только при редактировании комментария, который хотя бы один раз был опубликован. После этого значение не возвращается к `false`.
- Если комментарий ни разу не был опубликован, любое количество его редактирований сохраняет значение `edited = false`. 
- Признак `edited = true` означает, что комментарий был опубликован хотя бы один раз и затем изменён автором.

### Валидация

- Текст комментария обязателен.
- После удаления начальных и конечных пробелов длина текста должна составлять от 1 до 1000 символов.
- Пустой текст и текст, состоящий только из пробелов, не принимаются.
- Поддерживаются параметры пагинации `from` и `size`.

### API

- `POST /users/{userId}/events/{eventId}/comments` - создать комментарий
- `PATCH /users/{userId}/events/{eventId}/comments/{commentId}` - изменить свой комментарий
- `DELETE /users/{userId}/events/{eventId}/comments/{commentId}` - удалить свой комментарий
- `GET /users/{userId}/comments` - получить комментарии автора
- `GET /events/{eventId}/comments` - получить опубликованные комментарии события
- `GET /admin/comments` - получить комментарии для модерации
- `PATCH /admin/comments/{commentId}` - опубликовать или отклонить комментарий
